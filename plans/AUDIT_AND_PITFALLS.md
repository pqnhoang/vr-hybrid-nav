# AUDIT & PITFALLS — spec set vs. VL-Nav paper (arXiv:2502.00931v7)

Read together with `SYSTEM.md`. Part 1 lists every claim of the paper and where the specs implement it.
Part 2 lists deviations found during the audit and how the specs were corrected. Part 3 lists
implementation pitfalls (things that are easy to get wrong and silently break results).

Legend: ✅ faithful · 🔧 corrected in this revision · ⚠️ ambiguous in the paper (configurable) ·
➕ our addition (not in paper)

## Part 2 — Deviations found and corrections

**2.1 Angle reference (Eq. 1, Eq. 2).** The paper measures the FoV wedge and Δθ from the **robot**
position and heading. Earlier specs used the camera pose. With one forward-facing camera without yaw
offset both are identical; with several cameras (Spot) or a yawed mount, robot heading is wrong.
Correction: `exploration.angle_reference: robot | camera`, default `robot`; config validation
**must** reject `robot` when more than one camera is configured or a camera has a yaw offset
> 2°.

**2.2 Instance ranking.** Paper: "the one with the highest S_VL is selected". It does not say how
S_VL is computed for an instance point. Earlier spec used raw detection confidence. Correction:
`instance.instance_score: vl_eq3 | confidence`, default `vl_eq3` = Eq. 3 evaluated at the instance's
own bearing in the frame where it was detected (all relevant detections of that frame contribute),
max over frames. `confidence` kept as ablation.

**2.3 Eq. 8 grouping.** The text-extracted PDF shows `w_VL · S_VL(g) · S_unknown(g)` with stray
parentheses; we read it as `w_dist·S_dist + w_VL·(S_VL·S_unknown)`. Alternative reading
`(w_dist·S_dist + w_VL·S_VL)·S_unknown` changes behavior (curiosity would also scale distance).
Action for the user: verify in the rendered PDF. Spec keeps `scoring.form: additive_dist |
multiplicative_unknown` with the first as default.

Consequence of the default form worth knowing: when no relevant detections exist (all S_VL = 0) the
policy degenerates exactly to nearest-frontier, since S_dist > 0 always.

**2.4 Image memory in planning.** Abstract and contributions say the scene graph *and image memory*
support decomposition and replanning. Earlier spec sent text only by default. Correction:
`planner.planning_images: k` (default 4) best-view crops of the nodes most relevant to pending targets
are attached to decomposer/replanner prompts; ablation `--no-planning-images`.

**2.5 VL-score assignment timing.** Paper: assigned once when a point is first detected. With
multi-target tasks this means old frontiers never get a score for later subtasks. Our per-subtask
re-scoring is an addition. Correction: `vl.rescore_on_new_subtask: true | false` (false = strict
paper behavior), default `true`, documented as ➕.

**2.6 VL module prompt.** Fig. 3 shows a natural-language subtask ("Find the living room") feeding
the VL module. YOLO-World cannot detect rooms or long sentences reliably. We use
`detector_prompts` (short object phrases from the planner). For room-type subtasks the planner must
emit object proxies (sofa, TV) — enforced in `decompose.j2`. ➕

## Part 3 — Pitfalls (easy to get wrong)

### 3.1 Frames, geometry, time

1. **Gravity alignment with a tilted LiDAR.** Paper's Livox is tilted 23°. FAST-LIO's map frame
   (`camera_init`) is the first LiDAR/IMU frame, **not gravity-aligned**. Height thresholds of the
   occupancy grid, ground estimation and "yaw" all become wrong. Fix: gravity-align the map frame
   from static IMU accelerometer data at startup (or use an LIO that does), and verify the floor is
   at constant z across the whole map.
2. **Yaw of a pitched camera.** D455 tilted 7°: the camera heading is the optical z-axis projected
   onto the ground plane, not the raw rotation's yaw extracted with an arbitrary Euler convention.
3. **Optical vs ROS body frames.** Optical: z forward, x right, y down. ROS body: x forward, y left,
   z up. Mixing them in `T_cam_lidar` is the most common calibration bug.
4. **Bearing sign.** Pixel u grows to the right; CCW-positive bearing ⇒ μ = −atan((u−c_x)/f_x).
   Unit test with a synthetic detection left of center → μ > 0.
5. **Angle wrapping.** Every Δθ must be wrapped to (−π, π] before the |Δθ| ≤ h_fov/2 test and before
   Eq. 3, otherwise points behind the robot near ±π are mis-scored.
6. **h_fov from intrinsics**: h_fov = 2·atan(W / (2 f_x)), per camera, after any image resize.
7. **Clock offsets.** Camera (USB, host time) vs LiDAR (PTP or device time) can differ by tens of
   ms. At 1 rad/s rotation, 30 ms is ~1.7° → object centroids smear. Check with LiDAR-to-image
   overlays while the robot turns.
8. **Livox bag messages.** Livox driver often records `livox_ros_driver2/msg/CustomMsg`, not
   `PointCloud2`. `rosbags` needs the custom type registered; FAST-LIO consumes CustomMsg directly.
9. **Compressed images** in bags must be decoded (`cv2.imdecode`); check color order (BGR vs RGB)
   before feeding YOLO-World / the VLM.
10. **Habitat coordinates.** Habitat is Y-up with the agent looking along −Z; our system assumes
    Z-up, X-forward. Convert once in `HabitatSource` and unit-test with a known agent rotation.
11. **Habitat depth.** habitat-lab may normalize depth to [0,1] by min/max depth; disable
    normalization or rescale before back-projection.

### 3.2 Perception

12. **YOLO-World score scale.** Open-vocab scores are low (often 0.05–0.3). τ_det, `explore_candidate_score`
    and stop thresholds must be tuned per prompt type; do not reuse closed-set YOLO thresholds.
13. **TensorRT bakes the vocabulary.** Exporting YOLO-World (worldv2 only is exportable) fixes the
    classes at export time. Dynamic prompts from the planner therefore cannot be switched on a TRT
    engine. Options: PyTorch inference on the Orin (slower), or a fixed superset vocabulary exported
    once and filtered in software. Decide before real-robot deployment.
14. **`set_classes` cost.** Each call runs the CLIP text encoder. Cache by vocab hash; call only when
    the vocab changes (SYSTEM §4.2 already requires this).
15. **Mask edge leakage.** FastSAM masks bleed onto background; without erosion + MAD filtering the
    LiDAR median depth jumps to the wall behind thin objects (umbrella, chair legs).
16. **Sparse Livox depth.** One scan is too sparse for small objects; use a 0.5–1 s window, but
    long windows + pose error create ghost points. Tune together with clock offset.

### 3.3 Exploration

17. **Frontiers only inside the camera FoV.** LiDAR maps 360°, but frontiers are created only inside
    the wedge (paper Eq. 1). Space revealed by LiDAR outside the camera FoV can leave the map without
    any frontier → premature `no_frontier`. Mitigations (configurable ➕): initial in-place spin at
    each explore subtask, or `frontier.outside_fov: zero_score` to create frontiers outside the FoV
    with S_VL = 0.
18. **Weight scale.** S_dist = 1/(1+d) is ~0.1–0.3 at typical distances, S_VL·S_unknown ∈ [0,1].
    The ratio w_VL/w_dist decides when semantics beat proximity; sweep it before tuning anything else.
19. **Instance point on an obstacle.** The instance centroid is inside an occupied cell; planning
    straight to it fails. Use the approach point (exploration §6).
20. **δ_reached deadlock.** If every candidate is within δ_reached the robot holds forever; the
    `no_frontier_patience_s` event is the escape hatch.
21. **Oscillation** between two similar-score goals without hysteresis.

### 3.4 Planner / VLM

22. **Use the Instruct model, not Thinking.** Qwen3-VL-*-Thinking emits reasoning blocks that break
    strict JSON parsing.
23. **Structured-output API differs across vLLM versions.** Prefer the OpenAI-standard
    `response_format={"type": "json_schema", ...}`; keep the older `guided_json` path as fallback and
    test against the installed vLLM version.
24. **Image token budget.** Multiple full frames per call can exceed the context and VRAM on a 24 GB
    card. Limit `max_pixels` / resize crops; consider the FP8 checkpoint.
25. **Label mismatch** between VLM target names and detector labels ("rain jacket" vs "jacket") →
    empty top-k. Always embedding/synonym matching.
26. **Hallucinated node ids** → validated (planner §5.5), never executed blindly.
27. **Determinism.** `temperature=0` in vLLM is still not bit-reproducible across batch sizes; for
    open-loop evaluation cache VLM responses by prompt hash.
28. **Rooms outdoors** are meaningless; disable (`rooms.enabled: false`) to avoid garbage room labels
    steering the planner.

### 3.5 Evaluation

29. **Not comparable to paper numbers.** TIAMAT is not public; HM3D/GOAT-Bench results are proxies.
    Compare against baselines run in the same setup, not against Table I.
30. **HM3D ObjectNav episode versions.** VLFM's README uses ObjectNav HM3D v1 episodes; mixing v1 and
    v2 makes comparisons invalid.
31. **SPL** requires geodesic shortest-path length from the simulator, not Euclidean distance.
32. **MTUR** = mean execution time / max time limit; timed-out episodes count as 1.0.
