# TASK: Implement the Unified Memory module (VL-Nav re-implementation)

Reference: arXiv:2502.00931v7, Sec. III-A.1 ("Unified Memory System"). **Read `SYSTEM.md` and
`AUDIT_AND_PITFALLS.md` first.** Shared models (`Pose`, `Frame`, `FrameResult`, `Observation`,
`ObjectNode`, `RoomNode`), perception, `mapping.OccupancyGrid2D`, run modes and ROS 2 topics are
defined in `SYSTEM.md` and must not be redefined here. Paper-unspecified choices are **[DESIGN]**.

Consumers of this module: the planner (`TASK_nesy_task_planner.md`) and target acquisition
(`TASK_target_acquisition.md`), both only through the `MemoryView` protocol.

---

## 1. What the paper specifies

| Paper statement | Section here |
|---|---|
| Unified memory = 3D scene graph + object-centric image memory | §4, §7 |
| Scene graph with object nodes and room nodes, inspired by Hydra | §4 |
| Room masks from a room segmentation algorithm relying on morphological operations | §8.1 |
| An LLM labels each room from the object nodes connected to it | §8.3 |
| Object–room edge iff the object centroid falls inside the room mask | §9.1 |
| Object nodes generated by an open-vocabulary detector | §6 |
| Each object node stores (1) centroid, (2) highest detection confidence, (3) robot pose at that detection, (4) best-viewpoint RGB image | §4.1, §6.5, §7 |
| Memory grounds the planner's decomposition, replanning, top-k filtering and VLM verification | §5 |

Everything else (association, best-view rule details, room tracking, time semantics, mirroring) is
**[DESIGN]**.

## 2. Scope and interfaces

Inputs (per frame, from `runtime/`):
- `FrameResult` (detections, 3D observations, frame) from `perception.PerceptionPipeline`.
- `UpdateInfo` + shared `OccupancyGrid2D` from `mapping/` (memory never builds its own grid).
- Injected services: `TextEmbedder` (shared with acquisition), `LLMClient` (shared VLM endpoint,
  text-only use for room labels), `ImageStore`.

Outputs:
- `MemoryView` (read API for planner/acquisition), immutable snapshots, checkpoints on disk,
  JSON for `/memory/scene_graph`, best-view images for `/memory/best_view`, visualization data.

Out of scope: perception, occupancy mapping, planning logic, dynamic/moving objects, multi-floor
(single gravity-aligned floor; multi-floor = future work, keep `floor_id` field reserved).

## 4. Data model

### 4.1 Public (from `common.models`, SYSTEM §3)

`ObjectNode` and `RoomNode` exactly as defined in SYSTEM §3. The four paper attributes map to:
`centroid`, `best_score`, `best_view_pose` (+ `best_view_cam_pose`), `best_view_image_path`
(+ `best_view_bbox`).

### 4.2 Internal (`types.py`)

```python
class NodeState(BaseModel):          # mutable, never exposed directly
    node: ObjectNode
    voxels: set[tuple[int, int, int]]          # voxel keys at assoc_voxel_m (fast overlap test)
    label_votes: dict[str, float]
    score_history: list[tuple[float, float]]   # (t, score), capped
    best_view_history: list[tuple[float, str]] # (t, image ref) — needed for state-at-time-t (§10)
    created_t: float; updated_t: float
    version: int

class RoomState(BaseModel):
    room: RoomNode
    region_mask: np.ndarray            # bool, cropped to bbox
    bbox_cells: tuple[int, int, int, int]
    object_set_at_label: frozenset[int]  # objects used for the last label
    needs_label: bool

class MemoryEvent(BaseModel):         # for logging / debugging, not consumed by the planner
    t: float
    type: Literal["node_created", "node_merged", "best_view_updated", "node_pruned",
                  "nodes_deduped", "rooms_updated", "room_labeled"]
    payload: dict
```

### 4.3 Graph structure

| Edge | Rule | Stored? |
|---|---|---|
| object → room (`in`) | centroid in room mask (§9.1) | yes (`ObjectNode.room_id`, `RoomNode.object_ids`) |
| room ↔ room (`adjacent`) | regions touch (§8.1) | yes (`RoomNode.adjacent_room_ids`) |
| object ↔ object (`near`) | centroid distance ≤ r | no — computed on query (§9.2) |

## 6. Object pipeline

Called by `update(res, info)`. Order matters.

### 6.1 Rate limiting and gating

- Process at most `memory_rate_hz` frames per camera (others only update nothing).
- Drop observations with `score < min_obs_score`, fewer than `min_points` 3D points, range >
  `max_obs_range_m`, or bbox area < `min_bbox_area_px`.
- **[DESIGN]** `ignore_labels` (e.g. "floor", "wall", "ceiling") from config.

### 6.2 Intra-frame consolidation (`consolidate.py`) **[DESIGN]**

YOLO-World often returns several boxes for one object with different labels from the vocabulary
(e.g. "jacket" and "raincoat"). Before association, within one frame and camera:
- Group observations whose mask IoU ≥ `same_object_mask_iou` (default 0.7).
- Merge each group into one observation: union of points, `label_votes = {label: score}` for all
  members, `score = max`, bbox/mask of the highest-score member.
Without this step the map fills with co-located duplicates (AUDIT pitfall 34).

### 6.3 Association (`association.py`) **[DESIGN]**

For each consolidated observation `o`:
1. **Candidates**: nodes whose centroid is within `assoc_radius_m` (KD-tree, §9.2).
2. **Semantic gate**: pass if any label in `o.label_votes` equals a node label in
   `node.label_votes`, or text-embedding cosine ≥ `assoc_label_sim` between the top labels.
3. **Geometric score**: `overlap = |voxels(o) ∩ node.voxels| / |voxels(o)|` at `assoc_voxel_m`.
   Pass if `overlap ≥ assoc_overlap_min` or centroid distance < `assoc_close_m`.
4. **Cost** = `1 − overlap` (+ `w_dist · dist / assoc_radius_m`) for passing pairs.
5. **One-to-one per frame**: Hungarian matching between the frame's observations and candidate
   nodes, so two distinct objects seen in the same frame (two chairs) never merge into one node.
6. Unmatched observations → new nodes.

### 6.4 Node update (`object_map.py`)

- New node: `id` from a monotonically increasing counter (ids are never reused), `n_obs = 1`,
  `first_seen_t = last_seen_t = t`.
- Merge: add voxels (cap `max_node_voxels`, random-drop oldest when exceeded), centroid = median of
  voxel centers, `label_votes[l] += s` for each label, `label = argmax(label_votes)`, `n_obs += 1`,
  `last_seen_t = t`, `best_score = max(best_score, score)`.
- **Confirmed vs tentative** **[DESIGN]**: nodes with `n_obs < min_obs` are *tentative*;
  `MemoryView` hides tentative nodes unless `include_tentative=True`
  (`all_objects(..., include_tentative=False)` default). Exception: a tentative node with
  `best_score ≥ confirm_score` is confirmed immediately (rare objects seen once but clearly).

### 6.5 Best view

Paper: store the robot pose and RGB image at the highest-confidence detection. Implementation:

- Candidate view quality `q = score − border_penalty·[bbox touches image border] −
  small_penalty·[bbox area < best_view_min_area_px]` (both penalties default 0 → paper behavior).
- Replace best view iff `q > node.best_q + best_view_min_gain`. On replace: save frame to ImageStore,
  update `best_view_image_path`, `best_view_bbox`, `best_view_pose` (= `Observation.T_map_base`),
  `best_view_cam_pose`, append to `best_view_history`, emit `best_view_updated`.
- `best_score` always tracks the max raw score, independently of `q`.
- **Navigation consequence** (planner uses `best_view_pose` as the goal): optionally reject views
  whose base pose is in a cell that is now occupied/inflated in the grid (`best_view_require_free`).

### 6.6 Maintenance (`tick`)

- **Dedup** every `dedup_every_s`: pairs of confirmed nodes within `assoc_close_m` passing the semantic
  gate, or with voxel overlap ≥ `dedup_overlap_min` → merge into the older id; record alias
  `merged_id → kept_id` so ids held by the planner stay resolvable (`get_object` follows aliases).
- **Prune** every `prune_every_s`: tentative nodes older than `prune_age_s`; confirmed nodes are
  never pruned (no negative evidence in the paper). **[DESIGN] optional** `negative_evidence`:
  disabled by default.

## 7. Image memory (`image_store.py`)

- Stores **full frames** only when they become a best view of some node:
  `run_dir/images/{camera_id}_{stamp:.3f}.jpg` (quality `image_jpeg_quality`).
- One frame may be the best view of several nodes → reference counting; unreferenced frames deleted
  at checkpoint time **unless** referenced by a checkpoint still on disk (§10).
- `crop(ref, bbox, margin, max_px)` with an LRU cache; crops are generated on demand, not stored.
- Frames are written asynchronously (writer thread) so `update` never blocks on disk I/O.

## 8. Rooms

### 8.1 Segmentation (`rooms.py`) — morphological **[DESIGN details]**

Runs every `room_update_every_s` (or when the grid grew by more than `room_update_min_new_m2`).

1. `free = (grid == 0)` on a copy, optionally downsampled to `room_grid_res_m` (default 0.1 m).
2. Closing with disk `closing_kernel_m` to remove speckle; drop free components < `min_free_comp_m2`.
3. Erosion with disk radius `door_width_m / 2` → disconnects rooms at door openings.
4. Seeds = connected components (8-conn) of the eroded mask with area ≥ `min_seed_area_m2`.
5. Region growing back over `free`: watershed on `−distance_transform(free)` with seed markers,
   mask = `free`.
6. Merge regions < `min_room_area_m2` into the neighbor sharing the longest border.
7. Adjacency = regions sharing ≥ `min_shared_border_m` of border (4-conn).
8. Per room: `centroid_xy`, `area_m2`, polygon (for viz, `cv2.findContours` + simplification).

`rooms.enabled: false` (outdoors) → no room nodes, all objects `room_id = None`.

### 8.2 Room id tracking (`room_tracker.py`)

- IoU matrix between new regions and previous rooms (on the common grid frame).
- Hungarian matching with threshold `room_iou_min`: matched regions keep id and label.
- Split (one old → several new): the largest-IoU region keeps the id, others get new ids.
- Merge (several old → one new): keep the id with the largest IoU, record aliases for the others.
- Mark `needs_label` when: new id, or IoU with previous region < `relabel_iou`, or ≥
  `relabel_min_new_objects` objects changed since the last label.

### 8.3 Room labeling (`room_labeler.py`)

- Paper: an LLM infers the room label from the connected object nodes.
- Input per room: confirmed object labels with counts and mean `best_score`
  (top `room_label_max_objects`), room area, adjacent room labels if known.
- Prompt `memory/prompts/room_label.j2`; output JSON `{"label": str, "confidence": float}` with `label`
  constrained (enum) to `room_label_set + ["other"]`.
- Rooms with fewer than `room_label_min_objects` objects stay `"unknown"`.
- Runs in a worker thread with a queue; at most one request per room in flight; results applied only
  if the room's object set did not change meanwhile (else re-queued). Responses cached by
  (sorted object multiset, area bucket).
- Uses the planner's VLM endpoint in text-only mode; `MockLLMClient` for tests.

## 9. Edges and queries

### 9.1 Object–room assignment

On every room update and on every node create/merge:
- `room_id` = room whose mask contains the node centroid cell (paper).
- **[DESIGN]** fallback: nearest room within `room_assign_fallback_m`; else `None` (unassigned).
- Keep `RoomNode.object_ids` consistent (single function updates both sides).

### 9.2 Queries

- KD-tree over confirmed centroids, rebuilt lazily when `version` changed.
- `neighbors(node_id, radius_m, same_room)`: sorted by distance, excludes self, capped by
  `max_neighbors`.
- `find_by_text(text, min_sim, top_n)`: embedding similarity between `text` and node labels (cached
  label embeddings), tie-break by `best_score`. Used by the planner serializer and planning-image
  selection; acquisition uses its own `LabelMatcher` (same embedder).
- `best_view_crop(...)`: delegates to ImageStore.

## 10. Time semantics, snapshots, checkpoints (`snapshot.py`, `checkpoint.py`)

**Pitfall (AUDIT 33):** filtering the *latest* memory by `first_seen_t ≤ t` leaks the future — a node
first seen before t may have a centroid, label or best-view image acquired after t. That inflates
open-loop planner results.

Rules:
- `view()` returns the current state (live use: planner during replay or closed loop).
- `snapshot(t)` returns the exact state as of `t`, reconstructed from the latest checkpoint ≤ t
  (checkpoints every `checkpoint_every_s`, so granularity = that period). If `exact_snapshots: true`,
  replay observations from the checkpoint to t (observation log kept on disk as JSONL).
- `all_objects(until_t)` on `UnifiedMemory` = `snapshot(until_t).all_objects()` — never
  filter-only. (`InMemoryMemory` fixtures in the acquisition spec may filter, since fixtures are
  static.)
- Checkpoint = `graph.json` + `rooms.npz` (region masks) + `grid.npz` + image refs; images are shared
  between checkpoints (ref-counted, §7). Keep `max_checkpoints` (0 = all, for evaluation runs).

### 11.2 RemoteMemoryMirror (`remote_mirror.py`, ROS-free)

- `apply_scene_graph_json(json)`: replaces state if `version` is newer.
- `apply_best_view(node_id, image_name, jpeg_bytes)`: stores into a local mirror ImageStore.
- Missing image for a node → `best_view_crop` raises `ImageNotMirrored`; the planner node requests it
  via the `/memory/get_best_view` service (SYSTEM §7) and retries.
- Implements `MemoryView` (snapshot(t) supported only for t ≥ oldest mirrored version; otherwise
  raises).

## 12. Concurrency and performance

- Single writer (core process loop); readers get immutable `MemorySnapshot`s (structural sharing,
  no locks needed on the read path). Background threads: image writer, room labeler, optional room
  segmentation worker; they hand results back through a queue drained in `tick`.
- Budgets (Jetson Orin NX, indoor, ≤ 300 nodes): `update` ≤ 30 ms per frame excluding perception;
  room segmentation ≤ 300 ms on a 50 m × 50 m grid at 0.1 m; `view()` ≤ 2 ms. Measure in
  `MemoryStats` and log.

## 13. Visualization (`viz.py`)

- `render_topdown(snapshot) -> np.ndarray`: grid, rooms colored by id with labels, objects as dots
  with `#id label score`, best-view poses as arrows. Saved every checkpoint as PNG → the main manual
  inspection tool on bags.
- `marker_data(snapshot)`: ROS-free description consumed by `vlnav_ros` to publish
  `/memory/markers` (spheres per object colored by room, text labels, room polygons, room-adjacency
  lines).
- `best_view_gallery(snapshot, labels=None) -> np.ndarray`: grid of crops for quick review.

## 15. Milestones (M-IDs referenced in SYSTEM §9)

1. **M1 Types + consolidation + association**: synthetic observations — duplicate labels merged
   within a frame; two chairs in one frame stay two nodes (one-to-one); semantic gate with stub
   embedder; overlap vs close-distance pass.
2. **M2 ObjectMap + ImageStore**: create/merge, label voting flip, tentative→confirmed,
   best-view replacement (+ penalties), ref-counted deletion, async writer flush, dedup with aliases,
   pruning of tentative nodes only.
3. **M3 Rooms + tracker**: synthetic floor plans (2–4 rectangular rooms with doors of 0.8–1.0 m,
   one L-shaped room, one open-plan pair) → room count, adjacency; incremental growth keeps ids;
   split/merge cases; `rooms.enabled: false`.
4. **M4 Room labeler** (mock LLM): enum constraint, min-objects rule, relabel triggers, stale
   response discarded, cache hit.
5. **M5 UnifiedMemory + queries + snapshots**: edges consistency, fallback assignment, neighbors,
   `find_by_text`, `view()` immutability under concurrent updates, checkpoint save/load round-trip,
   `snapshot(t)` returns historical best view (test for the leakage pitfall), MemoryView
   conformance suite (shared with acquisition).
6. **M6 Serialization + RemoteMemoryMirror**: JSON round-trip, version ordering, missing-image
   path, aliases.
7. **M7 Real bag (mode A, memory only)**: run perception + mapping + memory over a bag; produce
   top-down PNGs per checkpoint, best-view gallery, stats; then the evaluation in §16 — manual
   checkpoint before planner work starts.

## 16. Evaluation (`eval/memory/`)

Uses the same `gt_objects.yaml` as the planner eval (planner spec §9), optionally with GT rooms:

```yaml
rooms:
  - {gt_id: bedroom_1, label: bedroom, polygon: [[0, 0], [4, 0], [4, 4.5], [0, 4.5]]}
```

| Metric | Definition |
|---|---|
| Object recall | GT objects with a confirmed node of a matching label (embedding ≥ 0.8) within `match_radius_m` (0.5) |
| Object precision | confirmed nodes matched to some GT object (only meaningful for annotated categories) |
| Duplicate rate | extra confirmed nodes per matched GT object |
| Centroid error | median / p90 distance node ↔ GT |
| Label accuracy | node label vs GT category |
| Best-view validity | fraction of best-view crops where the GT object is visible (manual spot check, 50 samples) |
| Room count error, room IoU | vs GT polygons (Hungarian on IoU) |
| Room label accuracy | matched rooms, label equality (or alias table) |
| Room assignment accuracy | GT object's room vs node's room |
| Runtime | `update` p50/p95, room segmentation p95, nodes over time |

Report recall/duplicates also over time (per checkpoint) — this is what the planner experiences.

## 17. Acceptance criteria

- `pytest -q` passes without GPU/network; memory imports nothing from `planner/`, `exploration/`,
  `acquisition/` (except the `MemoryView` protocol and `TextEmbedder`) or ROS 2.
- Same `MemoryView` conformance tests pass for `MemorySnapshot`, `RemoteMemoryMirror`,
  `InMemoryMemory`.
- No future leakage: `snapshot(t)` test passes.
- M7 artifacts produced on at least one real bag; metrics table from §16.
- Every **[DESIGN]** choice documented in `docs/design_choices.md`.

## 18. Open decisions (keep configurable)

- Association thresholds and the one-to-one matching cost (§6.3).
- Tentative/confirmed policy (`min_obs`, `confirm_score`).
- Best-view quality penalties (default 0 = paper's "highest confidence").
- Room segmentation parameters per environment; rooms disabled outdoors.
- Exact vs checkpoint-granular snapshots.
